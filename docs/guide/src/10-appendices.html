Appendix B

Command cheat sheet

Run the lab

docker compose --profile all up --build -d        # A–D, G on the default, Red Hat 21: :6180–6185
docker compose --env-file semeru-25.env \
  --profile all up --build -d                     # A–D, G on Semeru 25 (this guide): :8080–8085
docker compose up -d --build sized                # one scenario: naming it is enough
docker compose --env-file oracle-25.env \
  --profile all up -d                             # A–D, G on Oracle 25: :9080–9085
docker compose --profile all down                 # remove A–D, G (same --env-file)
docker compose --profile "*" down                 # remove everything

Your own sizing: the manual scenario (:x084), the plain up

docker compose up --build                         # Red Hat 21, 1 GiB, MaxRAMPercentage=75: :6184
docker compose --env-file temurin-21.env \
  --env-file manual.env up -d                     # JVM from file 1, sizing from file 2
LEAKLAB_MANUAL_MEM=768m \
LEAKLAB_MANUAL_JAVA_OPTS="-Xmx600m" \
  docker compose --env-file oracle-21.env up -d   # the shell wins over both files
docker compose --env-file temurin-21.env down     # remove it
# more: LEAKLAB_MANUAL_CPUS · _LOAD_MODE · _GUARDIAN · _GUARDIAN_THRESHOLD · _KEEP_RUNNING_ON_OOM
# PowerShell: $env:LEAKLAB_MANUAL_MEM="768m"

Drive load without the UI

curl -XPUT localhost:8080/api/load -H 'Content-Type: application/json' \
  -d '{"running":true,"mode":"HEAP","ratePerSecond":100,"payloadKb":512,"retentionPercent":40}'
# add "keepRunningOnOom":true to keep the engine on after an OOM (left out: unchanged; default false = pause)
curl -XPOST localhost:8080/api/load/burst -H 'Content-Type: application/json' -d '{"mode":"NATIVE","megabytes":64}'
curl -XPOST localhost:8080/api/memory/release
curl -XPOST localhost:8080/api/dumps/heap       # also: javacore | system

Inside a container

cat /sys/fs/cgroup/memory.max /sys/fs/cgroup/memory.current   # limit and usage (cgroup v2)
cat /sys/fs/cgroup/memory.events                               # max / oom / oom_kill counters
grep -E 'VmRSS|VmHWM' /proc/1/status                           # resident memory of the JVM
kill -QUIT 1                                                   # OpenJ9: javacore (+ heap dump with -Xdump:heap:events=user)
java -Xdump:what -version                                      # list active dump agents

Was it an OOMKill?

docker inspect -f '{{.State.OOMKilled}} {{.State.ExitCode}}' leaklab-overcommit-semeru-25
docker events --filter event=oom --since 1h --until "$(date -u +%FT%TZ)"
scripts/oomkill-forensics.sh docker
oc get pod -o jsonpath='{range .items[*]}{.metadata.name} {..lastState.terminated.reason} {..lastState.terminated.exitCode}{"\n"}{end}'
oc logs <pod> --previous
oc debug node/<node> -- chroot /host journalctl -k | grep -iE 'oom-kill|Killed process'
scripts/oomkill-forensics.sh k8s leaklab

JVM flags referenced in this guide

FlagEffect
-XX:MaxRAMPercentage=60Heap ceiling = 60 % of the container limit
-Xmx1gFixed heap ceiling. Ignores the container limit
-XX:MaxDirectMemorySize=96mCap on direct buffers
-XX:+ExitOnOutOfMemoryErrorExit after the first OOM (after the dump agents run)
-Xdump:directory=/dumpsWhere OpenJ9 writes all artefacts
-Xdump:heap:events=userHeap dump on SIGQUIT
-Xdump:java+heap:events=throw,filter=java/lang/OutOfMemoryError,msg_filter=*direct*,range=1..1Dumps for an OOM thrown by Java code (direct buffers), which the default systhrow agents ignore
-Xdump:heap:events=allocation,filter=#256mHeap dump on any single allocation ≥ 256 MiB
-Xverbosegclog:<file>,5,20000Rotating verbose GC log
--enable-native-access=ALL-UNNAMEDSilences Java 24+ restricted-native-access warnings
